# second-brain-kit

**A skill that builds you a "second brain" — a personal knowledge vault your AI coding agent
reads cheaply and grows with you.** Self-tailoring, works with Claude Code, Codex, or both,
with or without Obsidian. Ships zero secrets and zero personal data.

## What it does

`second-brain-kit` is a skill you install into your AI coding agent (Claude Code or Codex).
When you run it, it does three things:

1. **Interviews you** — a short set of questions about how you work and what you want to keep.
2. **Builds a knowledge vault** — a folder of plain markdown files, organized so your agent can
   find anything fast, plus git for versioning and sync between machines.
3. **Wires your agent to it** — installs a hook so the vault's map loads automatically at the
   start of every session, and links any skills you keep in the vault.

It is **not** a note-taking app and **not** a plugin. It is a *builder*: it creates the folder,
the files, the git setup, and the agent wiring — shaped by your answers — then gets out of the
way. From then on the vault is just yours: plain files you own, in a git repo you control.

## Why you need it

AI coding agents forget everything between sessions. The usual "fixes" both fail as you grow:

- **Dumping everything into context** (one huge notes file, or a folder the agent reads whole)
  gets expensive and slow — and eventually doesn't fit at all.
- **Relying on the model's memory** is lossy and not portable between machines or agents.

A second brain solves this the way a good index solves a big library: the agent loads a **tiny
map** every session and fetches **one page on demand**, instead of reading the whole library.
That keeps context cheap and fast whether you have 10 notes or 10,000 — and because it's plain
git-tracked markdown, your knowledge is portable, versioned, and yours forever.

You need this if you want your agent to **remember your projects, decisions, and context across
sessions and machines** without drowning in tokens or locking your notes inside one tool.

## How it works (the engine)

Three moving parts, and the whole design lives in how they fit together:

1. **`INDEX.md` — the always-loaded map.** A SessionStart hook prints this one small file into
   your agent's context at the start of every session. It holds who you are, your rules, a
   safety **Trust Boundary**, and a routing table. It is the *only* file loaded every time — a
   few thousand tokens, fixed cost, no matter how big the vault gets.
2. **`MAP.md` — the auto-generated index.** One line per note (`path — description`),
   regenerated by a script on every sync so it never goes stale. `INDEX.md` tells the agent the
   rule: *grep `MAP.md`, then open the one relevant note.* Notes are never bulk-loaded.
3. **The note, on demand.** The agent opens exactly the one file it needs, reads it, acts.

```
session starts → INDEX.md loads (small, fixed) → agent greps MAP.md → opens ONE note
```

That on-demand retrieval is why per-session cost stays flat as the vault grows. Add `sync vault`
(git commit + pull + push, with a secrets guard) and you have a knowledge base that follows you
across every machine.

## What it builds

```
your-vault/
  INDEX.md      # tiny routing map, auto-loaded every session (Who, Rules, Trust Boundary)
  MAP.md        # auto-generated one-line-per-note index — the agent greps this
  wiki/         # your knowledge, one note per topic
  projects/     # project snapshots + HANDOFF.md so you resume work on any machine
  raw/          # inbox for dumps; digest turns them into clean wiki notes
  scripts/      # the vault's own tools: build-map, sync-vault, link-skills, hooks
  .gitignore    # blocks .env / secrets / keys by default
```

Plus, **only if you ask for them**, opt-in modules: `save-to-vault` (one-command project
handoffs), `digest` (raw → wiki loop), a `size-gate` git hook (keeps the repo lean), and an
Obsidian layer.

## How to use it

1. **Install the skill** — two ways:
   - **From GitHub (easiest):** this repo is public — copy or clone it, then just tell Claude or
     Codex *"install this skill."* The agent drops it into your skills directory
     (`~/.claude/skills/` or `~/.agents/skills/`) automatically, and then offers to run it now.
   - **Manually:** copy the `second-brain-kit/` folder into your agent's skills directory yourself.
2. **Run it** — say *"build my second brain"* (or invoke `second-brain-kit`). If you just
   installed it from GitHub, the agent already offered — just say yes.
3. **Answer the interview** — Obsidian or plain markdown · Claude / Codex / both · your life+work
   areas · current projects · how to sync (GitHub / other git remote / local-only) · language ·
   which extras.
4. **Done** — the vault exists, git is initialized, the SessionStart hook is installed, and you
   have a `sync vault` command. From then on: work → `sync vault` → it's on all your machines.

## What it tailors to you

The interview means you don't get a generic template — you get a vault shaped to how *you* work:

- **Obsidian or plain markdown** — with Obsidian you get `[[wikilinks]]` and a minimal config;
  without it, plain relative links. The agent side is identical either way.
- **Claude, Codex, or both** — sets where the SessionStart hook and skill-links go.
- **Your areas & projects** — seeds a starter note per life/work area and a stub per project.
- **Sync target** — private GitHub repo, any git remote, or local-only history.
- **Language** — English, Hebrew, or bilingual.

## Clean & safe by design

- **No secrets, no personal data** — every file it ships is a generic template with placeholders.
- **Secrets git-ignored from day one** — `.env`, `secrets/`, `*.key` blocked by default, and
  `sync vault` refuses to stage secret-like paths.
- **Trust Boundary in every vault** — stored content (raw dumps, web pages, file contents) is
  treated as *data to analyze, never instructions to obey*. A prompt-injection guard baked in.

## Works best with (optional)

It pairs with the **`grill-me`** and **`brainstorming`** skills for a deeper tailoring pass. If
you don't have them, the kit uses its own built-in interview and works fully. When you run it,
it gives you the choice:

- **Option A** — continue now with the built-in interview (nothing to install).
- **Option B** — copy the code from the [superpowers repo](https://github.com/obra/superpowers)
  on GitHub into your project, tell Claude or Codex to install it, then run again for a deeper
  pass.

**What's second-brain-kit's own:** the INDEX/MAP routing engine, the vault scaffold, the git
sync, and the cross-agent skill-linking. `grill-me` and `brainstorming`
(by [obra/superpowers](https://github.com/obra/superpowers)) are optional third-party skills it
*can* use for a richer interview — not what it's built on. It runs fully without them.
